# Contributing factual knowledge

The goal of this repository is a small, high-trust corpus rather than comprehensive unreviewed documentation.

## Rules

1. Put factual content only under `tt-knowledge/`.
2. Start from `tt-knowledge/_templates/topic.md`.
3. Every indexed Markdown file must include front matter with `verified_by`, `verified_on`, and at least one `source`.
4. Prefer short, atomic statements. Separate architecture- or revision-specific facts explicitly.
5. Do not add facts inferred from chat, generated by an LLM, or copied from an unverified secondary source as authoritative statements.
6. If a fact changes, edit the existing current-truth document rather than leaving conflicting current values in separate files.
7. A human reviewer should verify both the statement and the cited source before merge.

## Suggested review questions

- Is every numeric value directly supported by a source?
- Does the statement identify the architecture/device/revision it applies to?
- Could an agent read the sentence out of context and misinterpret it?
- Does this conflict with an existing fact elsewhere in the corpus?
- Is the source authoritative enough for the claim being made?
